# ARCHITECTURE — SDU Hub

Микросервисы на **Python + FastAPI**, хранилище **PostgreSQL**, запуск через **Docker Compose**.
Разработка по **GitHub flow**: ветка на изменение → PR → merge в `main`.

## Карта сервисов

```
                 [ браузер / телефон студента ]
                              │ HTTPS
                              ▼
                     ┌──────────────────┐
                     │  gateway  :8000  │   единственная публичная точка входа
                     └────────┬─────────┘
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
  ┌───────────────┐   ┌────────────────┐   ┌─────────────────┐
  │ auth   :8001  │   │ moodle  :8002  │   │ tracker  :8003  │
  └───────┬───────┘   └───────┬────────┘   └────────┬────────┘
          │                   │                     │
          └───────────────────┼─────────────────────┘
                              ▼
                     ┌──────────────────┐
                     │ postgres  :5432  │
                     └──────────────────┘
                              ▲
                    moodle-service ──► https://moodle.sdu.edu.kz
```

## Зоны ответственности

| Сервис | Отвечает за | Не делает |
|---|---|---|
| `gateway` | маршрутизация, CORS, единый префикс `/api`, проверка сессии | не ходит в Moodle, не знает про токены |
| `auth-service` | обмен логина на токен Moodle, шифрование токена, сессии, выдача токена внутренним сервисам | не отдаёт токен наружу |
| `moodle-service` | клиент Moodle Web Services: курсы, оценки, файлы, дедлайны; прокси скачивания файлов | не хранит пароли |
| `tracker-service` | задачи и расписание студента (собственные данные) | не ходит в Moodle |

## Инварианты (из SECURITY.md)

1. Пароль студента живёт только внутри одного запроса в `auth-service` и нигде не сохраняется.
2. Токен Moodle хранится в БД **зашифрованным**, ключ — из переменной окружения.
3. Токен не выходит за пределы `auth-service` → `moodle-service`. Наружу — никогда:
   ни в JSON, ни в URL, ни в логах.
4. Файлы Moodle отдаются через `moodle-service`, который сам подставляет токен.
   В ссылке, которую видит браузер, токена нет.
5. Публичный запуск — только после разрешения IT-отдела СДУ (README, Фаза 1).

## Внутренняя коммуникация

Сервисы общаются по HTTP внутри docker-сети, наружу опубликован только `gateway`.
Внутренние вызовы подписываются общим секретом `INTERNAL_API_KEY` — чтобы `moodle-service`
не отвечал никому, кроме своих.
