# SDU Hub — студенческий помощник поверх Moodle SDU

Один экран, где студент SDU видит свои курсы, оценки, дедлайны и файлы из Moodle,
плюс личный трекер домашних заданий и дел. Цель — заменить неудобный вход в Moodle
на быстрый и приятный интерфейс, особенно на телефоне.

> Статус на 08.09.2026: **разрешение IT-отдела SDU получено, Фаза 1 закрыта.**
> Канал к Moodle работает, данные достаются. Идёт Фаза 2 — бэкенд на микросервисах.
> Технические правила `SECURITY.md` остаются в силе независимо от разрешения:
> пароль не хранится, токен — только зашифрованным и только внутри бэкенда.

## Что уже проверено (реальными запросами, не в теории)

Moodle SDU (`https://moodle.sdu.edu.kz`) — это Moodle версии 2024100711.04.
**Mobile Web Services на сервере включены** — это подтверждено тем, что официальное
приложение Moodle логинится, и тем, что запросы ниже вернулись с кодом `200`.

Проверено вручную через локальный прототип (`legacy/moodle-probe.html`), токеном
одного тестового аккаунта:

| Данные | Функция Moodle Web Service | Результат |
|---|---|---|
| Кто вошёл, имя, фото, userid | `core_webservice_get_site_info` | ✅ 200 |
| Список курсов студента | `core_enrol_get_users_courses` | ✅ 200 |
| Оценки по курсу | `gradereport_user_get_grade_items` | ✅ 200 |
| Содержимое курса (файлы, ресурсы) | `core_course_get_contents` | ✅ 200 |
| Ближайшие дедлайны (события) | `core_calendar_get_action_events_by_timesort` | ✅ 200 |

**Важный нюанс по данным.** На момент проверки семестр только начался, поэтому
реальных данных мало: 1 курс, оценки ещё не выставлены, дедлайнов 0, 5 файлов.
Это не ограничение API — это потому что преподаватели ещё не наполнили курсы.
Через несколько недель те же запросы вернут полный набор. **Не делай вывод, что
API отдаёт мало — он отдаёт всё, просто пока хранить в Moodle почти нечего.**

Также подтверждено ограничение браузера: **напрямую из браузера (страница, открытая
как файл) ходить в Moodle нельзя — CORS блокирует.** В прототипе это обходится
локальным Python-посредником. В настоящем сервисе к Moodle должен обращаться
**бэкенд**, а не фронтенд. Это не обход правил, это правильная архитектура.

## Как студент даёт доступ (без кражи паролей)

Единственный приемлемый способ получить оценки и файлы — **токен Moodle Mobile API**,
тот же механизм, что использует официальное приложение Moodle.

1. Студент вводит логин/пароль **один раз**, на экране входа сервиса.
2. Бэкенд обменивает их на токен:
   `GET /login/token.php?username=...&password=...&service=moodle_mobile_app`
   → ответ `{"token":"...","privatetoken":"..."}`
3. **Пароль после этого выбрасывается и НИКОГДА не сохраняется.**
4. Дальше сервис работает только по токену.

Токен — это секрет уровня пароля. Правила обращения с ним — в `SECURITY.md`.
Нарушение любого из них превращает учебный проект в утечку персональных данных.

## Архитектура (целевая)

```
[ Телефон / браузер студента ]
            │  HTTPS
            ▼
[ Бэкенд SDU Hub ]  ── обменивает логин на токен, шифрует и хранит токен,
     │                 ходит в Moodle от имени студента, отдаёт фронту чистый JSON
     ▼
[ Moodle SDU Web Services ]
```

- **Фронтенд** никогда не видит токен Moodle и не ходит в Moodle напрямую.
- **Бэкенд** — единственный, кто говорит с Moodle. Хранит токен зашифрованным.
- Трекер домашки/дел — отдельная таблица в БД, привязанная к студенту.

Стек (зафиксирован): **Python + FastAPI** на бэкенде, **PostgreSQL** для хранения,
запуск через **Docker Compose**. Бэкенд разбит на микросервисы — карта в `ARCHITECTURE.md`.
Фронт — React, за основу берётся готовый трекер из `legacy/homework-tracker.jsx`.

Разработка по **GitHub flow**: на каждое изменение отдельная ветка, дальше PR и merge в `main`.

- `services/` — микросервисы: gateway, auth, moodle, tracker.
- `shared/` — общий код сервисов.
- `web/` — фронтенд (Vite + React).

## Как запустить

```bash
cp .env.example .env          # заполнить TOKEN_ENCRYPTION_KEY и INTERNAL_API_KEY
make up                       # postgres + auth + moodle + tracker + gateway
npm --prefix web install
npm --prefix web run dev      # http://localhost:5173
```

Команды генерации секретов — в `.env.example`. Проверить, что бэкенд жив:
`curl http://localhost:8000/api/health`.

Тесты: `pytest` из корня.
